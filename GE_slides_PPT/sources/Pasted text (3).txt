## The actual gold-standard setup

Use a **single presentation repo**. Do not start from a blank `.pptx` each time.

Your setup should have:

* a **`.potx` template** for theme, fonts, colors, slide size, and base layouts
* a **code generator** that fills only approved layouts
* a **story file** that defines the argument slide by slide
* a **data/assets folder** for charts, diagrams, and visuals
* a **QA pass** in PowerPoint before delivery

The reason this works better than prompting raw slide content into an assistant is that it separates the hard parts correctly: story logic, visual system, content population, and final polish. Microsoft explicitly supports saving reusable templates as `.potx`, and 16:9 is the default modern slide size for new presentations. ([Microsoft Support][4])

## The best workflow

### 1. Build the deck as a system, not a file

Create one master template with only **6–8 approved layouts**. For example:

* title / opener
* section divider
* one-message chart slide
* process / flow slide
* comparison slide
* architecture / layered diagram slide
* dense appendix evidence slide
* closing recommendation slide

This is where PptxGenJS is valuable: it supports master slides and reusable branding structures in code, so your layouts become fixed assets instead of being reinvented every time. ([gitbrent.github.io][5])

### 2. Make the AI generate a storyboard first

Before any slide rendering, have the agent produce:

* the audience
* the decision the deck must drive
* the top-line answer
* a 10–20 slide storyline
* a one-sentence takeaway title for every slide
* the visual type for each slide

That is the highest-leverage use of the model. The biggest mistake is asking for “beautiful slides” too early. The model should first behave like a strategy consultant or editorial lead, not a decorator.

### 3. Render from structure, not from vibes

Use a file like `storyboard.yaml` or `deck.json` with fields such as:

* `slide_title`
* `assertion`
* `layout_type`
* `key_visual`
* `source_data`
* `speaker_notes`
* `appendix_ref`

Then let the agent fill those into PptxGenJS. This keeps every revision controllable. When slide 7 changes, you regenerate instead of manually nudging boxes for 20 minutes.

### 4. Finish in PowerPoint desktop

Code should get you to about 85–90%. The last 10–15% should happen in PowerPoint:

* spacing
* object alignment
* image crop
* transitions only if needed
* presenter notes review
* accessibility check
* optional Section Zoom for complex live navigation

Microsoft’s docs support using Zoom to jump among sections/slides during presentation, and their accessibility guidance is worth treating as part of the final QA, not an afterthought. ([Microsoft Support][6])
